1.1.1	Expand the structure of Digital Rate Filing (DRF) / Premium Rating Portal (PRP) to support Pricing Strategy 2.0 rating 
model, the addition or elimination of rating elements with required business rating rules.

1.1.3	Business rules which currently control the exclusion of renewals from auto processing as well quoting blackout periods 
must be included. 

1.1.4	Regulatory Rate Filing must also be supported, specifically, classification wording, terminated classifications with 
companion replacements.

Examples: Editing Rate Filing Start/End date
1. Status: Draft
Rule: You can edit both the Start and End dates.
Scenario: An actuary (Creator) starts a new rate filing for the upcoming year.
They initially set the Start Date to 01/01/2026 and the End Date to 12/31/2026.
After a planning meeting, the business decides to align the launch with a new marketing campaign. The actuary can easily go back into the Draft filing and change the dates to a Start Date of 02/01/2026 and an End Date of 01/31/2027.
Why: This is the creation phase. Maximum flexibility is needed.

2. Status: Review or Ready for Approval
Rule: You can edit neither the Start nor the End date.
Scenario: The Creator finishes their work and submits the Draft for review. The status changes to Review.
A Reviewer is now examining the filing. The Start and End dates (02/01/2026 - 01/31/2027) are now read-only.
If the Reviewer notices the dates are wrong, they cannot fix them directly. They must Reject the filing, which sends it back to the Draft status. The Creator can then correct the dates and resubmit.
Why: This ensures data stability. Reviewers and Approvers must be confident that the fundamental scope of what they are approving (the rating period) is not changing underneath them.

3. Status: Approved or UAT Approved
Rule: You can edit both the Start and End dates again.
Scenario: The filing has been approved and is now in the UAT (User Acceptance Testing) environment. The QA team is testing it.
During testing, they discover a dependency on another system that won't be ready by 02/01/2026. The project manager decides to push the launch back by two weeks.
An authorized user (e.g., UAT Approver or Admin) can go into the UAT Approved filing and change the Start Date to 02/15/2026 and the End Date to 02/14/2027.
Why: This allows for adjustments based on testing feedback or external business factors before the filing goes live to production.

4. Status: Published
This is the most restrictive status, as the filing is live and actively being used by the Rating Engine.

Rule: You cannot edit the Start Date, but you can edit the End Date (with special conditions).
Scenario: A rate filing is Published with a period of Start Date 01/01/2025 to End Date 12/31/2025. The next rate filing has been delayed. The business needs to extend the current period.
Editing Start Date: An authorized user cannot change the 01/01/2025 start date. It's historical and immutable.
Editing End Date: An authorized user can extend the 12/31/2025 end date. For example, they can change it to 01/31/2026.
However, section 5.5.1 adds three critical sub-rules for editing the End Date of a Published filing:

5.5.1.1 (90-Day Rule): You can't edit the end date if you are within 90 days of it.
Example: If today is November 15, 2025, you are within 90 days of 12/31/2025. The system will block you from changing the end date. This prevents last-minute, potentially disruptive changes to a live rating period. If today were September 15, 2025, you would be allowed to edit it.
5.5.1.2 (End > Start): The new end date must be after the start date.
Example: You can change the end date to 01/31/2026, but you cannot change it to 12/30/2024. This is a basic data integrity check.
5.5.1.3 (One-Time Edit): You can only perform this extension once.
Example: The user successfully extends the end date to 01/31/2026. A week later, they realize they need to extend it again to 02/28/2026. The system will block this second change. This rule enforces that extensions should be a rare, well-planned exception, not a routine activity.
